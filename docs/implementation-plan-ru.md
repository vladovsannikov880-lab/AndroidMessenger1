# План развития AndroidMessenger1 под задание

## 1) Текущее состояние проекта (аудит)

На текущий момент приложение находится на стартовой стадии:

- Есть 3 Activity: `MainActivity`, `LoginActivity`, `RegisterActivity`.
- Firebase уже подключен (Auth + Realtime Database + Analytics, `google-services.json` есть в проекте).
- UI и бизнес-логика генерации постов, хранения списка, редактирования и работы с изображениями пока не реализованы.

## 2) Архитектура под 3 уровня задания

Рекомендуется переход на структуру:

- `ui/` (Activity/Fragment + adapters)
- `data/` (Firebase repositories + DTO)
- `network/` (клиент к AI API)
- `domain/` (use-cases: generate text, generate image, save post)

Минимальный стек для Java-проекта:

- `RecyclerView` для списка постов.
- `Retrofit + OkHttp + Gson` для AI API.
- `Firebase Auth` для регистрации/авторизации.
- `Firebase Realtime Database` (или Firestore) для метаданных постов.
- `Firebase Storage` для изображений (на уровне 3 обязательно).

## 3) Подходящие AI API, доступные в РФ

### Текст
1. **GigaChat API (Sber)**
   - Российский провайдер, документация и SDK на русском.
   - Подходит для генерации постов по промпту.

2. **Yandex Cloud Foundation Models (YandexGPT)**
   - Доступ через REST/gRPC/OpenAI-совместимый режим.
   - Удобно для масштабирования и разных моделей.

### Изображения
1. **YandexART (через Yandex Foundation Models)**
   - Нативная интеграция в Yandex Cloud.

2. **Kandinsky / FusionBrain API**
   - Российский сервис генерации изображений.

## 4) Реализация по уровням

### Уровень 1 — генерация текста + список + редактирование

Функционал:
- Экран создания поста:
  - поле `prompt`;
  - кнопка `Сгенерировать`;
  - результат текста;
  - кнопка `Сохранить`.
- Экран списка постов (`RecyclerView`):
  - `title` (первые 40-60 символов текста);
  - `createdAt`.
- Экран редактирования поста:
  - редактирование текста;
  - сохранение изменений в Firebase.

Модель данных `Post`:
- `id`
- `userId`
- `prompt`
- `text`
- `title`
- `createdAt`
- `updatedAt`
- `imageUrl` (nullable)

### Уровень 2 — генерация изображения + предпросмотр единого поста

Функционал:
- Кнопка `Сгенерировать изображение` по текущему prompt/тексту.
- Загрузка картинки:
  - в память/кэш для предпросмотра;
  - в галерею телефона через `MediaStore`.
- Экран Preview:
  - текст + картинка как единый пост;
  - кнопка `Сохранить пост`.

Хранение:
- `imageUrl` в Firebase Storage (или временно локальный URI на уровне 2).

### Уровень 3 — аккаунты + облачная синхронизация

Функционал:
- Регистрация/логин/логаут через Firebase Auth.
- Изоляция данных по `userId`.
- Синхронизация постов и изображений в облако:
  - текст/метаданные в Database/Firestore;
  - изображения в Firebase Storage.

Правила безопасности:
- Firebase Rules: пользователь читает/пишет только свои посты.

## 5) Предлагаемая схема в Firebase

Вариант Realtime Database:

- `/users/{uid}/profile`
- `/posts/{uid}/{postId}`

Поля `posts/{uid}/{postId}`:
- `prompt`, `text`, `title`, `imageUrl`, `createdAt`, `updatedAt`.

Storage:
- `/post_images/{uid}/{postId}.jpg`

## 6) Технический план внедрения (порядок)

1. Добавить модель `Post` и репозиторий Firebase.
2. Реализовать `PostListActivity` + адаптер.
3. Реализовать `CreatePostActivity` (prompt → text generation API).
4. Реализовать `EditPostActivity`.
5. Подключить генерацию изображений и Preview.
6. Доделать `LoginActivity`/`RegisterActivity` и маршрутизацию по auth state.
7. Настроить Firebase Rules.
8. Добавить обработку ошибок API, retry и индикаторы загрузки.

## 7) Что важно для продакшн-качества

- **Не хранить API ключи в APK**: выносить AI вызовы на backend/proxy (Cloud Functions/свой сервер).
- Ввести лимиты запросов и логирование использования.
- Использовать `WorkManager` для фоновых загрузок/повторов.
- Обрабатывать офлайн-режим (кэш списка постов).
